# Recetas de discovery por stack

Las **recetas concretas** (`Glob`/`Grep`, convenciones de frameworks, señales) que usa
`sdd-documentacion-arquitectura` para inventariar y trazar el codebase. El skill define la
**estrategia**; este archivo define **cómo se ejecuta en cada stack**.

> **Cómo usar este archivo.**
> 1. Leé §1 del perfil (`docs/standards/perfil-proyecto.md`): lenguajes y frameworks. En monorepos,
>    repetí por cada paquete de `paquetes`.
> 2. Aplicá primero la sección **Común** (sirve para cualquier stack) y después la del stack.
> 3. Las rutas reales salen de §4 del perfil: los globs de abajo son **convenciones por defecto**;
>    si §4 declara otra cosa, manda §4. El eje de agrupación sale de §6.
> 4. Una receta que no devuelve nada **no prueba ausencia**: probá la variante del framework o
>    registrá `no_encontrado`. Nunca completes el hueco con lo "típico" del framework.
> 5. No trasladar heurísticas de un stack a otro.
>
> Notación: `Glob: <patrón>` y `Grep: pattern=... glob=... output_mode=...` son las herramientas del
> agente. `<raiz>` = raíz de código de §4; `<kw>` = palabra clave del módulo/eje; `<Simbolo>` =
> función/clase que se está trazando. Todo hallazgo se registra con `archivo:línea`.

# Común (cualquier stack)

### E1 — Inventario documentable (solo rutas + 1 línea de propósito)

Antes de explorar, **verificá si `docs/_index.yaml` existe**: si existe, usá las entradas
`pending`/`stale` como lista de trabajo y no re-explores lo `documented` fresco. Si no existe,
construí el inventario completo. En modo exhaustivo no filtres por relevancia: cada unidad cohesiva
es candidata.

```bash
# Manifests y lockfiles → stack, versiones, monorepo
Glob: **/{package.json,pnpm-workspace.yaml,turbo.json,nx.json,pyproject.toml,requirements*.txt,Pipfile,pom.xml,build.gradle*,settings.gradle*,*.csproj,*.sln,go.mod,go.work,composer.json,Gemfile}
#   (excluir node_modules/, vendor/, .venv/, bin/, obj/, build/, dist/, target/)

# Estructura de primer nivel del código → candidatos a módulos / valores del eje de §6
Glob: <raiz>/*/
Glob: <raiz>/*/*/

# Despliegue y procesos → qué procesos corren (web, worker, scheduler)
Glob: **/{Dockerfile,docker-compose*.yml,compose*.yaml,Procfile,serverless.yml,app.yaml,fly.toml,vercel.json,netlify.toml}
Glob: **/{k8s,helm,charts,deploy,infra}/**/*.{yml,yaml}

# Contratos explícitos
Glob: **/{openapi,swagger}*.{json,yml,yaml}
Glob: **/*.{proto,graphql,gql,avsc}
Glob: **/schemas/**/*.json

# Migraciones y esquemas de DB
Glob: **/{migrations,migrate,db/migrate,alembic/versions,Migrations}/**
Glob: **/{schema.prisma,schema.rb,structure.sql,*.sql}

# Configuración y flags
Glob: **/{.env.example,.env.sample,.env.template,config/**,settings/**,appsettings*.json,application*.{yml,yaml,properties}}
Grep: pattern="(feature[_-]?flag|isEnabled\(|launchdarkly|unleash|flagsmith|growthbook|openfeature|split\.io)" -i output_mode="files_with_matches"

# CI → qué se construye/testea/despliega (contexto, no se ejecuta)
Glob: {.github/workflows/*.yml,.gitlab-ci.yml,azure-pipelines*.yml,Jenkinsfile,.circleci/config.yml,bitbucket-pipelines.yml}

# Documentación existente (§7) → no duplicar
Glob: docs/**/*.md
Glob: **/{README,ARCHITECTURE,CONTRIBUTING,ADR*}*.md
```

Código de §3 (generado / vendorizado) se lista con marca `generado`/`vendor`: señales típicas
`// Code generated ... DO NOT EDIT`, `@generated`, `auto-generated`, carpetas `generated/`, `gen/`,
`__generated__/`, `vendor/`, `third_party/`.

```bash
Grep: pattern="(DO NOT EDIT|@generated|auto-generated|autogenerated)" -i output_mode="files_with_matches"
```

### Fase 3 — Integraciones salientes (genérico)

```bash
# URLs y hosts hardcodeados o por config
Grep: pattern="https?://[a-zA-Z0-9.-]+" glob="<raiz>/**" output_mode="files_with_matches"
Grep: pattern="(_URL|_HOST|_ENDPOINT|_BASE_URL|_API_KEY)\b" output_mode="files_with_matches"

# Colas / eventos / streaming (nombres de brokers y SDKs)
Grep: pattern="(kafka|rabbitmq|amqp|sqs|sns|pubsub|nats|redis.*(publish|subscribe|xadd)|eventbridge|servicebus|eventhub|kinesis)" -i output_mode="files_with_matches"

# Storage, email, SMS, pagos, auth externos
Grep: pattern="(s3|blob.?storage|gcs|cloudinary|sendgrid|mailgun|ses|smtp|twilio|stripe|mercadopago|paypal|adyen|auth0|cognito|keycloak|okta|firebase)" -i output_mode="files_with_matches"

# Webhooks entrantes
Grep: pattern="webhook" -i output_mode="files_with_matches"
```

Por cada integración registrar: sistema, protocolo, dirección, dónde se configura (variable),
timeouts/retries/idempotencia y manejo de errores — con `archivo:línea`.

### Fase 4 / A1-A3 — Señales de decisión arquitectónica (genérico)

- **Carpeta/capa `shared`, `core`, `common`, `kernel`, `platform` con abstracciones sobre infra**
  - Categoría de ADR candidato: Patrón transversal
  - Receta: `Glob: <raiz>/{shared,core,common,kernel,platform,lib}/**`
- **Tabla/clase `outbox`, `inbox`, `saga`, `event_store`**
  - Categoría de ADR candidato: Consistencia / mensajería
  - Receta: `Grep: pattern="(outbox|inbox|saga|event.?store|idempoten)" -i`
- **Retry, backoff, circuit breaker**
  - Categoría de ADR candidato: Resiliencia de integraciones
  - Receta: `Grep: pattern="(retry|backoff|circuit.?breaker|resilience4j|polly|tenacity|p-retry|cockatiel)" -i`
- **Multi-tenancy**
  - Categoría de ADR candidato: Modelo de datos
  - Receta: `Grep: pattern="(tenant_?id|tenantId|multi.?tenant|row.?level.?security)" -i`
- **Soft delete / auditoría / versionado de filas**
  - Categoría de ADR candidato: Modelo de datos
  - Receta: `Grep: pattern="(deleted_?at|is_?deleted|soft.?delete|paranoid|audit|created_by|updated_by|version\b)" -i`
- **Monkey-patching / override de librería**
  - Categoría de ADR candidato: Override de framework
  - Receta: ver receta A1 del stack
- **`patch-package`, `patches/`, forks en el manifest**
  - Categoría de ADR candidato: Override de dependencia
  - Receta: `Glob: patches/**` · `Grep: pattern="(git\+|github:|#fork)" glob="**/package.json"`
- **Bifurcación de negocio con 3+ ramas por tipo/estado/tenant**
  - Categoría de ADR candidato: Decisión de negocio
  - Receta: `Grep: pattern="(switch|match|case|when)\s*\(?.*(type|status|kind|tenant|plan|country)" -i output_mode="files_with_matches"`
- **Caché explícita (invalidación propia)**
  - Categoría de ADR candidato: Consistencia / performance
  - Receta: `Grep: pattern="(cache|memoize|ttl)" -i output_mode="files_with_matches"`
- **Feature flags que conviven con dos implementaciones**
  - Categoría de ADR candidato: Migración progresiva
  - Receta: receta de flags de E1

Criterio ADR vs. module: ver el SKILL. Ante la duda, module.

### S1-S5 — Domain summary (genérico)

- **S1 — Alcance** — `Glob: <raiz>/**/<kw>*/**` y `Grep: pattern="<kw>" -i output_mode="files_with_matches"` → agrupar por capa (rutas/UI, servicios, modelos, jobs). Cruzar con los entrypoints de la Fase 1 del stack
- **S2 — Capas y dependencias** — Imports entrantes y salientes de la carpeta del eje (receta de imports del stack en [trazado](#trazado)): quién depende del eje y de qué ejes depende
- **S3 — Modelo de datos** — Recetas de modelos/migraciones del stack filtradas por `<kw>`; enums/estados: `Grep: pattern="(enum|Enum|StrEnum|TextChoices|sealed class)" glob="<ruta del eje>/**"`
- **S4 — Docs y orquestadores existentes** — `Glob: docs/conceptos/<kw>*/**` · entradas del eje en `docs/_index.yaml` · entrypoints de la Fase 1 filtrados por `<kw>`
- **S5 — Proceso central** — El servicio/caso de uso con más dependencias entrantes del eje; buscar `calculate|compute|process|reconcile|match|score|price|quote` en la carpeta del eje

### F1-F5 — Flows (genérico)

- **F1 — Disparador / orquestador** — Entry point de la Fase 1 del stack (ruta, consumidor, job, comando, acción de UI) → la función/clase que coordina los pasos
- **F2 — Cadena de llamadas** — [Recetas de trazado](#trazado): definición del símbolo, callers, resolución de interfaces/DI
- **F3 — Puntos de decisión** — `Grep: pattern="(if|switch|match|case|when|guard|throw|raise|return err)" path="<archivo del paso>" output_mode="content" -n` acotado a la función; validaciones (`zod|yup|joi|pydantic|class-validator|FluentValidation|@Valid|validates`)
- **F4 — Mutaciones de datos** — Recetas de persistencia del stack (`save|create|update|delete|insert|upsert|commit`) acotadas a la cadena; transacciones (`transaction|@Transactional|atomic|BeginTransaction|Tx`); eventos emitidos (`emit|publish|dispatch|send|produce`)
- **F5 — Integraciones y config** — Recetas de Fase 3 acotadas a la cadena; lectura de config (`process.env|os.environ|getenv|@Value|IConfiguration|config\(|ENV\[`)

# JavaScript / TypeScript

- **Entrypoints / bootstrap** — `package.json` → `main`, `bin`, `scripts.start/dev`, `exports` · `Glob: <raiz>/{main,index,server,app}.{ts,js,mjs}` · `Grep: pattern="(\.listen\(|NestFactory\.create|createServer\(|serve\(\{|export default \{\s*fetch)"`
- **Rutas / endpoints (backend)** — Express/Koa/Fastify/Hono: `Grep: pattern="(router|app|fastify|server)\.(get|post|put|patch|delete|route)\("` · NestJS: `Grep: pattern="@(Controller|Get|Post|Put|Patch|Delete|Resolver|Query|Mutation|MessagePattern|EventPattern)\("` · tRPC: `Grep: pattern="(publicProcedure|protectedProcedure|router\(\{)"` · GraphQL: `Glob: **/*.{graphql,gql}`
- **Rutas (fullstack / meta-frameworks)** — Next.js app router: `Glob: {app,src/app}/**/{page,layout,route}.{ts,tsx,js,jsx}` · pages router: `Glob: {pages,src/pages}/**/*.{ts,tsx,js,jsx}` (`pages/api/**` = endpoints) · Server Actions: `Grep: pattern="['\"]use server['\"]"` · Remix/React Router: `Glob: app/routes/**` · Nuxt: `Glob: {pages,server/api,server/routes}/**` · SvelteKit: `Glob: src/routes/**/+{page,layout,server}*.{ts,js,svelte}`

- **React Native / mobile** — Navegación: `Grep: pattern="(createNativeStackNavigator|createBottomTabNavigator|Stack\.Screen|expo-router)"` · Expo router: `Glob: app/**/*.{tsx,jsx}` · Nativo: `Glob: {ios,android}/**` (solo inventario)
- **Modelos / esquemas DB y migraciones** — Prisma: `Glob: **/schema.prisma`, `Glob: prisma/migrations/**` · TypeORM: `Grep: pattern="@Entity\("`, `Glob: **/migrations/*.ts` · Sequelize: `Grep: pattern="(sequelize\.define|extends Model|@Table)"` · Drizzle: `Grep: pattern="(pgTable|mysqlTable|sqliteTable)\("`, `Glob: drizzle/**` · Mongoose: `Grep: pattern="new (mongoose\.)?Schema\("` · Knex: `Glob: **/migrations/*.{js,ts}` · Kysely/SQL crudo: `Grep: pattern="(\.raw\(|query\(.(SELECT|INSERT|UPDATE))"` y template tags `sql` sobre literales
- **Validación / contratos** — `Grep: pattern="(z\.object\(|yup\.object\(|Joi\.object\(|@Is[A-Z]\w+\(|t\.type\(|Type\.Object\()"`
- **Jobs / colas / cron** — `Grep: pattern="(new (Queue|Worker)\(|@Processor\(|@Process\(|@Cron\(|cron\.schedule\(|node-cron|agenda\.define|bree|setInterval\()"` · Serverless: `serverless.yml` `functions:` / `Glob: **/{functions,lambdas,handlers}/**` · Vercel/Netlify cron: `vercel.json` `crons`
- **Integraciones externas** — `Grep: pattern="(axios\.create|axios\.(get|post)|fetch\(|got\(|ky\.|undici|new [A-Z]\w*Client\(|@aws-sdk/|@google-cloud/|@azure/|stripe\(|kafkajs|amqplib|@nestjs/microservices)"`
- **Config / flags** — `Grep: pattern="process\.env\.[A-Z_]+"` · `Grep: pattern="import\.meta\.env\."` · `Glob: **/{config,configuration}.{ts,js}` · `@nestjs/config`, `dotenv`, `envalid`, `t3-env`: `Grep: pattern="(ConfigService|createEnv\(|cleanEnv\(|dotenv)"`
- **DI / middlewares** — NestJS: `Grep: pattern="@(Module|Injectable|UseGuards|UseInterceptors)\("` · Express: `Grep: pattern="app\.use\("` · Next middleware: `Glob: {middleware,src/middleware}.{ts,js}`
- **A1 — overrides** — `Glob: patches/**` (patch-package) · `Grep: pattern="(\.prototype\.\w+\s*=|declare module ['\"])"` (monkey-patch / module augmentation) · `pnpm.overrides`/`resolutions` en `package.json`

**Heurísticas JS/TS**

| Señal | Significado |
|---|---|
| `"use client"` / `"use server"` | Frontera cliente/servidor (Next.js / React Server Components) |
| `app/**/route.ts`, `pages/api/**` | Endpoint HTTP en un meta-framework |
| `*.module.ts` + `@Module` | Módulo NestJS = unidad documentable natural |
| `libs/`, `packages/` con `package.json` propio | Paquete de monorepo → module o valor del eje |
| `*.d.ts` bajo `types/` o `@types/` propio | Contratos/augmentations; no es lógica |
| `generated/`, `__generated__/`, `*.gen.ts` | Código generado (§3) |

- **Entrypoints / bootstrap** — `Glob: **/Program.cs`, `Glob: **/Startup.cs` · `Grep: pattern="(WebApplication\.CreateBuilder|Host\.CreateDefaultBuilder|CreateHostBuilder|FunctionsApplication)"` · `*.sln` / `*.csproj` (`<OutputType>Exe</OutputType>`, `Sdk="Microsoft.NET.Sdk.Web"`)

- **UI** — Razor/Blazor: `Glob: **/*.{razor,cshtml}` + `Grep: pattern="@page \""` · MAUI/WPF: `Glob: **/*.xaml`
- **Modelos / esquemas DB y migraciones** — EF Core: `Grep: pattern="(: DbContext\b|DbSet<|IEntityTypeConfiguration<|OnModelCreating)"` · migraciones: `Glob: **/Migrations/*.cs` (excluir `*.Designer.cs` y `*ModelSnapshot.cs` de la lectura; sí del inventario) · Dapper: `Grep: pattern="\.(Query|Execute)(Async)?<?\w*>?\("` · FluentMigrator/DbUp: `Grep: pattern="(\[Migration\(|DeployChanges\.To)"`
- **Validación / contratos** — `Grep: pattern="(AbstractValidator<|\[Required\]|\[StringLength|\[Range)"` · DTOs: `Grep: pattern="public record \w+(Request|Response|Dto)"`
- **Jobs / colas / cron** — `Grep: pattern="(: BackgroundService\b|IHostedService|RecurringJob\.|BackgroundJob\.Enqueue|IJob\b|\[DisallowConcurrentExecution\]|TimerTrigger|ServiceBusTrigger|QueueTrigger)"` · mensajería: `Grep: pattern="(IConsumer<|MassTransit|NServiceBus|IHandleMessages<|ServiceBusProcessor|IRequestHandler<|INotificationHandler<)"` (MediatR incluido)
- **Integraciones externas** — `Grep: pattern="(HttpClient\b|IHttpClientFactory|AddHttpClient|Refit|RestSharp|Flurl|BlobServiceClient|AmazonS3Client|ServiceBusClient|IProducer<)"`
- **Config / flags** — `Glob: **/appsettings*.json` · `Grep: pattern="(IConfiguration|IOptions<|IOptionsSnapshot<|Configure<|GetSection\(|IFeatureManager|FeatureGate)"`
- **DI / cross-cutting** — `Grep: pattern="(builder\.Services\.Add|services\.Add(Scoped|Singleton|Transient)|UseMiddleware<|IMiddleware|IActionFilter|IPipelineBehavior<)"`
- **A1 — overrides** — Reemplazos de servicios del framework: `Grep: pattern="(Replace\(ServiceDescriptor|RemoveAll<|Decorate<|services\.Replace)"` · `override` sobre clases base del framework (`SaveChanges`, `OnModelCreating`, `HandleAsync`)

**Heurísticas .NET**

| Señal | Significado |
|---|---|
| Proyectos `*.Domain`, `*.Application`, `*.Infrastructure`, `*.Api` | Clean architecture: cada proyecto es una capa |
| `override SaveChanges(Async)` en el `DbContext` | Auditoría / soft delete / eventos de dominio → candidato a ADR |
| MediatR `IRequestHandler<>` | Cada handler es un caso de uso (entry de flow) |
| `obj/`, `bin/`, `*.g.cs`, `*.Designer.cs` | Generado (§3) |

# Infra / IaC y data

- **Terraform / OpenTofu** — `Glob: **/*.tf` · módulos: `Grep: pattern="^module \""` · recursos: `Grep: pattern="^resource \""` · backends/estado: `Grep: pattern="backend \""` · variables por ambiente: `Glob: **/*.tfvars` (inventariar, no leer valores sensibles)
- **Pulumi / CDK / Bicep / CloudFormation** — `Glob: **/{Pulumi.yaml,cdk.json,*.bicep}` · `Grep: pattern="(new (aws|azure|gcp)\.|AWSTemplateFormatVersion|Resources:)"`
- **Kubernetes / Helm** — `Glob: **/{Chart.yaml,values*.yaml,kustomization.yaml}` · `Grep: pattern="^kind: (Deployment|StatefulSet|CronJob|Job|Service|Ingress)"` → procesos, jobs programados y exposición
- **dbt** — `Glob: dbt_project.yml`, `Glob: models/**/*.sql`, `Glob: models/**/*.yml` (tests y docs) · fuentes: `Grep: pattern="source\("`, linaje: `Grep: pattern="ref\("`
- **Orquestadores de datos** — Airflow/Prefect/Dagster en [Python](#python) · Spark: `Grep: pattern="(SparkSession|spark\.read|\.write\.)"` · notebooks: `Glob: **/*.ipynb` (solo inventario)

En IaC, el "flow" típico es el **camino de una petición** (DNS → CDN → balanceador → servicio →
datos) y el **pipeline de despliegue**; los ADRs típicos son elecciones de servicio gestionado,
topología de red y estrategia de estado. Si §2 del perfil dice que la IaC es de otro equipo, se
inventaría como contexto y no se documenta como propia.

<a id="trazado"></a>
# Recetas de trazado (F2) por lenguaje

Cómo encontrar **dónde se define** un símbolo, **quién lo llama** y **qué implementación concreta**
se usa detrás de una interfaz.

- **JS/TS**
  - Definición: `Grep: pattern="(function|const|class|interface|type) <Simbolo>\b|<Simbolo>\s*[:=]\s*(async\s*)?\("`
  - Callers: `Grep: pattern="\b<Simbolo>\("` + `Grep: pattern="import .*\b<Simbolo>\b"`
  - Implementaciones / DI: `Grep: pattern="implements <Interfaz>\b"` · Nest: `Grep: pattern="provide:\s*<Token>"`
  - Imports del eje (S2): `Grep: pattern="from ['\"].*<carpeta-eje>"`
- **Python**
  - Definición: `Grep: pattern="(def|class) <Simbolo>\b"`
  - Callers: `Grep: pattern="\b<Simbolo>\("` + `Grep: pattern="import .*<Simbolo>\b"`
  - Implementaciones / DI: `Grep: pattern="class \w+\(.*<Base>.*\)"` · FastAPI `Depends(<fn>)`
  - Imports del eje (S2): `Grep: pattern="(from|import) .*<paquete_eje>"`
- **Java/Kotlin**
  - Definición: `Grep: pattern="(class|interface|record|enum|fun|object) <Simbolo>\b"` · métodos: `Grep: pattern="\s<Simbolo>\("`
  - Callers: `Grep: pattern="\.<Simbolo>\("`
  - Implementaciones / DI: `Grep: pattern="(implements|extends|:) .*<Interfaz>\b"` · `@Qualifier`, `@Primary`, `@Bean` que la devuelve
  - Imports del eje (S2): `Grep: pattern="^import .*\.<paquete_eje>\."`
- **.NET**
  - Definición: `Grep: pattern="(class|interface|record|enum|struct) <Simbolo>\b"`
  - Callers: `Grep: pattern="\.<Simbolo>(Async)?\("`
  - Implementaciones / DI: `Grep: pattern=": .*\b<IInterfaz>\b"` · registro: `Grep: pattern="Add\w+<<IInterfaz>,\s*\w+>"`
  - Imports del eje (S2): `Grep: pattern="^using .*\.<Namespace>"`
- **Go**
  - Definición: `Grep: pattern="^func (\(\w+ \*?\w+\) )?<Simbolo>\(|^type <Simbolo> "`
  - Callers: `Grep: pattern="\.<Simbolo>\(|\b<Simbolo>\("`
  - Implementaciones / DI: métodos del tipo: `Grep: pattern="^func \(\w+ \*?<Tipo>\) "`; quién satisface la interfaz: buscar los métodos de la interfaz
  - Imports del eje (S2): `Grep: pattern="\"<modulo>/.*<paquete_eje>\""`
- **PHP**
  - Definición: `Grep: pattern="(function|class|interface|trait|enum) <Simbolo>\b"`
  - Callers: `Grep: pattern="(->|::)<Simbolo>\("`
  - Implementaciones / DI: `Grep: pattern="implements .*<Interfaz>\b"` · bindings del contenedor
  - Imports del eje (S2): `Grep: pattern="^use .*\\\\<Namespace>\\\\"`
- **Ruby**
  - Definición: `Grep: pattern="(def (self\.)?|class |module )<Simbolo>\b"`
  - Callers: `Grep: pattern="(\.|::)<Simbolo>\b"`
  - Implementaciones / DI: `include`/`prepend`/herencia: `Grep: pattern="< <Base>\b|include <Modulo>\b"`
  - Imports del eje (S2): constantes del eje: `Grep: pattern="<ModuloEje>::"`

Si el entorno tiene un language server o herramientas de "go to definition / find references",
preferilas: son más precisas que el grep. Si un símbolo se resuelve dinámicamente (reflexión,
`getattr`, `send`, strings en un registro de handlers, convención de nombres del framework),
registralo como **"resolución dinámica — Suposición"** y citá dónde se registra.
